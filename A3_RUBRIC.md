# 3004ENG AT3 PEP rubric — Exceeds vs don’t-dos

Source: Griffith LMS rubric `3004ENG AT3_PEP` (screenshots `A3Rubric1.png`, `A3Rubric2.png`).  
Submission: one PDF or Word file per team; Turnitin on; Excel / ProjectLibre / MS Project may sit beside the report.  
Total: **40 points**. Target every criterion at Exceeds.

How to use this file while editing: the **Do (Exceeds)** list is the bar. The **Don’t** list is every behaviour the lower bands punish (Mastery / Near / Below / No Evidence). Hitting a Don’t drops the criterion, even if the rest looks strong.

## 1. Executive summary — 2 pts

A senior decision maker could approve or decline **from this section alone**.

### Do (Exceeds)

- State **purpose**, **scope**, **headline budget with contingency**, **key milestone dates**, **critical risks with consequence**, and a **clear recommendation**.
- Every figure and date **matches the body exactly**.

### Don’t

- Write an introduction instead of a decision document.
- Imply the recommendation; fail to say approve / decline.
- Omit purpose, scope, budget+contingency, milestone dates, or risk consequences.
- Name risks without consequence; list milestones without dates.
- Lean on the rest of the plan for context the board still needs.
- Let any number or date disagree with Sections 2–8.
- Paste the Charter summary, or leave the section so thin it gives no basis for a decision.
- Use generic “ask the board to proceed” language that does not say what is being approved.

## 2. Refined project overview — 3 pts

Show a project the team understands **far better than Week 4**.

### Do (Exceeds)

- Identify **every** change to scope, objectives, stakeholders, milestones, or the project itself (a change table is the example they give).
- Explain **each** change by **what the team learned**.
- Right-size scope to the plan that follows.
- Changing direction is allowed **if you explain why**. A Charter that held is also Exceeds if the learning is visible.

### Don’t

- Restate the Charter with cosmetic edits.
- List changes with little or no explanation.
- Hide changes so a marker must diff against the Week 4 document to see them.
- Leave the learning-to-change link vague (Mastery ceiling).
- Keep an unscoped megaproject the schedule and budget cannot deliver.
- Contradict the rest of the plan.
- Skip the refined overview.
- Invent A1 defects the charter did not contain.
- Remap numbered objectives (Obj 4 stays LRR; Obj 5 stays the November window).

## 3. Schedule management — 8 pts

Network with float; critical path **derived**; Gantt agrees; compression **calculated**.

### Do (Exceeds)

- Network logic as a **diagram** and/or a **table with early and late dates**.
- Show **dependencies**, **float**, and a **correctly derived** critical path.
- Network, Gantt, and milestone list **agree**.
- Baseline dates are **realistic for the WBS**.
- Compression worked **with numbers**: which activities, by how much, added cost or **cost slope**, new duration, and risks created (**rework, resource overload, quality, secondary risks**).
- Prose says **why this option beat the alternative**.
- Native files (if uploaded) **agree with the report**.

### Don’t

- Assert the critical path instead of deriving it from float.
- Leave network logic incomplete.
- Let Gantt and network disagree (dates, links, or which bars are critical).
- Describe compression in prose without a calculation.
- Give compression cost without the risks created.
- Justify the method only in a sentence (Mastery ceiling: costs present, risks brief, choice not fully justified).
- Write the compression scenario as a paragraph without numbers.
- Omit network logic, omit the Gantt, or omit compression entirely.
- Produce a schedule that has no relationship to the WBS and budget.
- Crash a bar that is not on a $TF=0$ path that actually sets $T$-0 (e.g. crashing stacking while A-113 still gates hot fire).

## 4. Cost management — 5 pts

A budget a **board could sign**.

### Do (Exceeds)

- Every cost line **traces to a WBS element** (any structured WBS format is fine).
- Totals **reconcile with the executive summary**.
- **Assumptions sit next to the numbers**.
- Credible sources: Rawlinsons, supplier quotes, published rates, comparable projects, or a **stated parametric basis**, cited in **footnotes or APA**.
- **Inclusions and exclusions** are explicit.
- Contingency **sized and justified against the risk register** (RES Contingency Guideline or expected value), **not a flat percentage with no reason**.

### Don’t

- Use a flat contingency percentage with no reasoning.
- Leave lines with no visible basis.
- Map only part of the budget to the WBS.
- Leave several assumptions unstated.
- Cite inconsistently, thinly, or not at all.
- Let figures look invented.
- Skip exclusions or skip contingency.
- Let Section 1 dollars disagree with Section 4.
- Publish numbers with no assumptions, no sources, and no link to scope or schedule.
- Put Option C compression dollars into the work baseline if they are a contingent draw.

## 5. Resource management — 4 pts

Roles for **this** pad; demand vs capacity **shown**; conflicts have an **escalation path**.

### Do (Exceeds)

- Roles and responsibilities **specific to this project** (RACI or equivalent fits well).
- Allocation **tied to the schedule**.
- **Show** where demand peaks, **where it exceeds capacity**, and what you would do (**levelling, smoothing, hiring, resequencing**) with the **schedule or cost consequence**.
- Conflict resolution = a **practical escalation path for resource conflicts on the project**.

### Don’t

- Describe peaks in prose instead of showing them (Mastery ceiling).
- Use a generic conflict-resolution / values statement (“we will communicate respectfully”).
- Write roles and strategies that could apply to any project.
- Disconnect resources from the actual schedule.
- List roles only.
- Restate textbook levelling / smoothing definitions without applying them.
- Copy Team Charter roles, or omit the section.
- Exceed the pad occupancy cap in the “mitigated” picture without a named response.
- Invent overtime heads on top of surge if the plan already replaced them.

## 6. Risk management — 6 pts

15–20 risks that could **only** belong to this campaign; register and plan **agree**.

### Do (Exceeds)

- **15 to 20** risks unique to **this project and this plan**.
- Schedule risks → **actual critical-path activities**.
- Cost risks → **actual budget lines**.
- Delivery risks → **the chosen procurement route**.
- Each row: **cause ≠ event**, probability and impact on a **stated scale**, **named owner**, response that is an **action**, **residual rating that follows from the response**.
- Prose on the **top risks** and how **contingency, float, and the delivery model** respond to them.
- **Register and plan agree**.

### Don’t

- Include generic rows such as “weather” or “budget overrun” with no project-specific cause.
- Let residual ratings ignore the stated response.
- Keep owners or responses vague.
- Dump a table with little prose analysis.
- Use fewer than 15 risks, or leave a required field blank across many entries.
- Isolate the register from schedule, cost, or delivery.
- File no register, fewer than ten risks, or a table with no analysis.
- Use heat-map scores as money; EMV must come from $P\% \times I\$$.
- Invent a payload LEO geometry or other A1-foreign driver to justify compression.

## 7. Delivery and control — 8 pts

Five live controls, each applied to **this** campaign, explained in **prose**.

The five elements (from the Exceeds cell): **governance**, **delivery model**, **quality**, **HSE**, **EVM**.

### Do (Exceeds)

- **Governance:** named roles, decision rights, reporting cadence.
- **Delivery model:** EPC, EPCM, design-and-construct, alliance, or another model suited to the discipline; justified against **at least one alternative** and against **this project’s risk profile, scope certainty, and client capability**.
- **Quality:** named standards and verification points.
- **HSE:** the **actual hazards of this work**.
- **EVM:** performance measurement baseline; how PV and EV will be measured; metrics **CPI, SPI, EAC**; **thresholds that trigger action**.
- Each element **explained in prose, not only tabulated**.

### Don’t

- Tabulate controls with no prose (kills Exceeds even if the tables are complete).
- Treat alternatives in one clause and leave EVM thresholds thin (Mastery ceiling).
- Leave one or two of the five elements generic.
- Choose a delivery model with limited justification.
- Describe EVM as a textbook concept rather than a framework for this project.
- Name a delivery model with no justification.
- Omit EVM, or give a definition only.
- Omit one or more of the five elements.
- Pick a model unsuited to the project with no reasoning, or leave the section largely absent.
- Use EVM “dashboard history” as if the campaign had already been executed, unless the status is clearly illustrative.

## 8. Integration and professionalism — 4 pts

One document, one team, one set of numbers.

### Do (Exceeds)

- Scope, WBS, schedule, budget, resources, risks, and delivery describe the **same project**.
- **Every number agrees wherever it appears**.
- Title page, contents, numbered headings, consistent formatting.
- Figures and tables **labelled and referred to in the text**.
- Referencing in **one style** (footnotes or APA; either accepted).
- Contribution appendix **complete and signed by all members**; cover-page percentages **total 100%**.

### Don’t

- Let milestone dates (or dollars, IDs, owners) differ between summary and schedule.
- Leave a figure unreferenced, numbering inconsistent, or one section in a different voice (Mastery ceiling).
- Mix reference styles.
- Present unevenly.
- Show visible stitching between authors/sections.
- Make the plan harder to follow through poor presentation.
- Leave the contribution appendix incomplete or unsigned.
- Let sections contradict each other.
- Ignore formatting requirements.
- Omit the contribution appendix.
- Let cover percentages fail to sum to 100%, or disagree with the appendix.

## Cross-cutting don’t-dos (any section can fail Integration)

These are the traps that also knock other criteria:

1. **Charter dump** — restating A1 instead of refining it (Overview Below; Exec No Evidence).
2. **Number drift** — a date or dollar in Section 1 that is not the YAML/body value (Exec Near; Integration Near/Exceeds fail).
3. **Unscoped megaproject** — factory, payload ops, or LEO insertion treated as this consultancy’s finish line (Overview Below).
4. **Asserted logic** — critical path, occupancy, or contingency stated without a derivation (Schedule / Resource / Cost).
5. **Generic PM textbook** — roles, risks, EVM, or conflict resolution that could fit any project (Resource / Risk / Delivery Near–Below).
6. **Tables without prose** — especially compression choice, top risks, delivery-model scoring, and EVM thresholds (Schedule / Risk / Delivery).
7. **Flat contingency** — a percentage with no link to the register (Cost Exceeds kill).
8. **Unsigned / missing contribution appendix** (Integration Below / No Evidence).

## Exceeds checklist (one pass before submit)

- [ ] Board can approve from Section 1 alone; recommendation is a sentence, not implied.
- [ ] Section 1 dates and dollars = body = YAML.
- [ ] Change table: every material A1→A3 move, each with what was learned; Obj 4/5 identities unchanged.
- [ ] Network has ES/EF/LS/LF/TF; two $TF=0$ paths into hot fire are derived; Gantt matches.
- [ ] Compression: activities, days, cost/slope, new duration, four risk types, why not the alternative.
- [ ] Every cost line → WBS; inclusions/exclusions; sources cited; contingency = residual EMV + RES, not a naked %.
- [ ] RACI is this pad; peak **shown**; response named with cost/schedule effect; escalation path, not values.
- [ ] 15–20 campaign-specific risks; cause ≠ event; residual follows treatment; prose ties contingency, float, D&C.
- [ ] Governance, D&C vs EPC, quality holds, pad HSE, EVM bands — all in prose.
- [ ] Contribution appendix signed; cover % = 100%; one voice; every figure called in text.
